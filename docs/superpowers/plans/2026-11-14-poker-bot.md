# Покер-бот — план реализации

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Telegram-бот для общего чата: учёт закупов/докупов inline-кнопками, сверка банка со
стеками и минимальный список переводов.

**Architecture:** `core/` — чистая логика без I/O (деньги, расчёт, правила игры). `platform/` —
тонкая обёртка под Cloudflare Workers + D1 (webhook, Bot API через `fetch`, SQL). При переезде на
Telegram Serverless переписывается только `platform/`.

**Tech Stack:** JavaScript (ESM), Cloudflare Workers, D1 (SQLite), `node --test`, `node:sqlite`
для тестов БД, wrangler (только dev-зависимость).

**Spec:** `docs/superpowers/specs/2026-11-14-poker-bot-design.md`

## Global Constraints

- Ноль npm-зависимостей в рантайме; в `devDependencies` только `wrangler`.
- Деньги — целые **копейки** (`number`, промежуточные произведения — `BigInt`). Фишки — целые. Никаких float в суммах.
- Без внешних ключей в схеме БД (`REFERENCES`/`FOREIGN KEY` запрещены).
- Секреты (`BOT_TOKEN`, `WEBHOOK_SECRET`) — только `wrangler secret` / `.dev.vars`; репозиторий публичный.
- Тексты бота — на русском. Деньги выводятся с запятой: `34,25`; в режиме «Округлить» — `34`.
- `callback_data` ≤ 64 байт, формат `<gameId>:<action>[:<arg>]`.
- Node ≥ 24 (есть `node:sqlite`).
- Коммиты — без трейлеров `Co-Authored-By` и упоминаний AI.

## Review Focus

1. **Повторная доставка webhook** (Telegram ретраит при не-200/таймауте) — один update не должен создать два докупа. Тест: один и тот же `update_id` дважды → одна запись (Task 6).
2. **Мусор во вводе стека**: `1 370`, `-5`, `1370.5`, `Вася Пупкин 800`, неизвестное или неоднозначное имя — бот отвечает понятной ошибкой, стек не пишется. Тесты в Task 3 (`parseStackInput`, `resolvePlayer`).
3. **Кнопки старой игры** (отменённой/рассчитанной) — нажатие не меняет данные, всплывает «Игра уже закончена». Тест в Task 6.
4. **Команды с суффиксом бота** в группе: `/game@cash_bot 1000 50` работает как `/game 1000 50`. Тест в Task 6.
5. **`message is not modified`** от `editMessageText` (два одинаковых обновления подряд) — не ошибка, обработка не падает. Тест в Task 5.

**Files:**

**Interfaces:**
- Produces:
  - `parseMoney(text: string): number|null` — копейки; принимает `50`, `50.5`, `50,25`; `null` для ≤0, >2 знаков после запятой, не-числа.
  - `formatKop(kop: number, opts?: {whole?: boolean}): string` — `3425 → "34,25"`, `5000 → "50,00"`; `whole: true` → `"34"`.
  - `roundToTotal(nums: bigint[], denom: bigint): number[]` — каждое `nums[i]/denom` в целые копейки; сумма результата = `Σnums/denom`, округлённое до ближайшего (.5 вверх). Метод наибольших остатков: floor каждого, недостающие единицы — элементам с наибольшей дробной частью, при равенстве — меньшему индексу.
  - `splitEvenly(total: number, n: number): number[]` — `total` копеек на `n` долей: база `trunc(total/n)`, первые `|total mod n|` долей получают ещё `sign(total)`. Это правило спеки «неделимые копейки — первым по порядку входа».
  - `roundWhole(balances: number[]): number[]` — каждый баланс до кратного 100 (ближайшее, .5 от нуля), затем `-(сумма)` прибавляется к элементу с максимальным балансом (при равенстве — меньший индекс).

### Task 3: `core/game.js` — правила игры

**Files:** Create `core/game.js`, `test/game.test.js`

**Interfaces:**
- Consumes: `roundToTotal`, `splitEvenly`, `roundWhole`, `parseMoney` (Task 1); `minTransfers` (Task 2); `GameSnapshot`.
- Produces:
  - `parseGameArgs(args: string): {chipsPerBuyin:number, priceKop:number}|null` — `"1000 50"`, `"1000 50,5"`; фишки — целое > 0.
  - `activeEntries(g): Entry[]`; `buyinsOf(g, playerId): number`; `bankChips(g): number`; `investedKop(g, playerId): number`.
  - `missingStacks(g): Player[]`; `discrepancyChips(g): number` = Σстеков − банк (только когда стеков нет недостающих).
  - `balances(g, {split: boolean}): number[]` — копейки по `g.players`; throw `'missing_stacks'` / `'discrepancy'` (если ≠0 и `!split`).
  - `settlement(g, {split: boolean, round: boolean}): {balances:number[], transfers:{from:number,to:number,kop:number}[]}` — `from/to` = **player.id**.
  - `parseStackInput(text: string): {name: string|null, chips: number}|null` — последний токен — целое ≥ 0 из цифр; всё до него — имя (trim, может содержать пробелы); пусто → `name:null`.
  - `resolvePlayer(players: Player[], name: string): {player: Player}|{error: 'not_found'|'ambiguous'}` — сравнение без регистра, сначала точное, потом по префиксу.
  - `rebuyTargets(g, tgUserId: number): Player[]` — сам игрок (если в игре) + все гости.
  - `playerByTg(g, tgUserId): Player|undefined`.
  - `undoTarget(g, tgUserId): Entry|null` — последняя неотменённая запись с `createdBy === tgUserId`.

  Баланс (C = chipsPerBuyin, p = priceKop):
  1. `value = roundToTotal(stacks.map(s => BigInt(s)*BigInt(p)), BigInt(C))` — стек в копейках.
  2. `invested_i = buyins_i · p`; `D = Σvalue − Σinvested` (целое).
  3. `D ≠ 0` и `!split` → throw `'discrepancy'`; иначе `share = splitEvenly(D, N)`.
  4. `balance_i = value_i − invested_i − share_i` (сумма ровно 0).
  5. `round: true` → `roundWhole(balances)`.

  - Банк: 3 игрока, у Паши 1 докуп → `bankChips=4000`; отменённый докуп не считается.
  - Без расхождения: Паша 2 закупа, Дима и Саша по 1 (price 5000), стеки `[1370, 2630, 0]` → `[-3150, 8150, -5000]`.
  - Нечётный курс: price 5050, стеки `[333, 1667]` при 2 закупах → сумма балансов строго 0, значения целые.
  - Расхождение +1000 фишек (3 игрока, price 5000): `split:false` → throw `'discrepancy'`; `split:true` → доли `[1667,1667,1666]` вычтены из балансов, сумма 0.
  - Расхождение −1000 + split → доли `[-1667,-1667,-1666]`, сумма 0.
  - `round:true` → все балансы кратны 100, сумма 0, остаток у максимального.
  - Недостающий стек → throw `'missing_stacks'`.
