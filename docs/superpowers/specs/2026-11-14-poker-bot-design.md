# Покер-бот: учёт докупов и расчёт платежей — дизайн

Дата: 2026-11-14

## Зачем

Компания друзей периодически играет в покер на деньги. Две проблемы:

1. **Теряются докупы.** Начальный закуп никто не записывает, докупы пишут текстом в общий
   чат и иногда забывают. В конце фишек на столе больше (или меньше), чем внесено денег, и
   непонятно, откуда расхождение.
2. **Расчёт в конце.** Нужно раскидать деньги минимальным числом переводов.

Решение — Telegram-бот в общем чате компании: докуп отмечается одной inline-кнопкой, бот
сверяет банк со стеками и выдаёт минимальный список переводов.

## Цели

- Отметить закуп/докуп — одно нажатие.
- Все в чате видят актуальное состояние: кто сколько вложил, сколько в банке.
- Игрок не из чата может присоединиться по пересланной ссылке; игрока без Telegram можно
  добавить гостем.
- Закончить игру в любой момент с текущими стеками; стеки произвольные («десятки, сотни»).
- Показать расхождение банка и стеков; дать «Дописать докуп» или «Разделить на всех».
- Минимальное число переводов, суммы до копейки; отдельной кнопкой — округлённый вариант.

## Не цели

- Бот не переводит деньги и не интегрируется с банками — только список «кто кому сколько».
- Нет статистики и истории игр в интерфейсе (данные в базе остаются — можно добавить позже).
- Нет турниров, разных сумм докупа, разных курсов внутри одной игры.
- Нет нескольких одновременных игр в одном чате.

## Анти-цели (провал, даже если «работает»)

- Докуп требует больше одного-двух нажатий или ввода текста — тогда опять забудут.
- Бот теряет игру посреди вечера (перезапуск, деплой).
- Две одновременные отметки докупа — и одна потерялась.
- Итог расчёта не сходится до нуля (кто-то «потерял» копейку).

## Подход

Рассмотренные варианты:

| Вариант | Плюсы | Минусы |
|---|---|---|
| **A. Cloudflare Workers + D1 (выбран)** | JS в V8-изоляте и SQLite — та же модель, что у Telegram Serverless; бесплатно, без карты | Нужна учётка Cloudflare; позже переезд |
| B. Python/aiogram + AWS Lambda + DynamoDB | Остаётся Python/aiogram | Нужна карта; при переезде в Telegram Serverless — переписывать всё |
| C. Ждать Telegram Serverless | Сразу целевая платформа | Пользователь в waitlist, сроки неизвестны |
| (отброшено) SQLite-файл / память на своём сервере | Просто | Нужен свой сервер; память теряет игру при рестарте |

Пользователь выбрал **A** с прицелом переехать на Telegram Serverless
(https://core.telegram.org/bots/serverless), когда дадут доступ.

Следствия выбора:
- Язык — **JavaScript** (ESM). Python-заготовка (`pyproject.toml`, `uv.lock`, `.venv`,
  aiogram) удаляется.
- **Без npm-зависимостей в рантайме**: в Telegram Serverless их нет. Bot API вызывается через
  `fetch`. Dev-зависимости (wrangler) допустимы.
- Схема БД — **без внешних ключей** (Telegram Serverless их не поддерживает).

## Архитектура

```
core/        чистая логика, без I/O и платформы, тесты на node --test
  settle.js    балансы → минимальный список переводов
  money.js     фишки → копейки, распределение остатков, округление
  game.js      правила игры: кто может что, валидация, подсчёт банка/расхождения
platform/    обёртка под Cloudflare (при переезде переписывается только она)
  worker.js    приём webhook, проверка секрета, роутинг update'ов
  telegram.js  тонкий клиент Bot API на fetch
  db.js        запросы к D1
  views.js     тексты и клавиатуры сообщений
migrations/  SQL-миграции D1
test/        тесты core/
```

Webhook: `setWebhook` с `secret_token`; worker отклоняет запросы без правильного заголовка
`X-Telegram-Bot-Api-Secret-Token`. Секреты (токен бота, webhook secret) — в секретах
Cloudflare, не в репозитории.

## Данные

Всё в целых: фишки — целые, деньги — **копейки (целые)**. Никаких float в суммах.

- `games`: id, chat_id, message_id игрового сообщения, chips_per_buyin, price_kop_per_buyin,
  status (`active` ⇄ `counting` → `settled`; из `active`/`counting` → `cancelled`),
  created_at, created_by.
- `players`: id, game_id, tg_user_id (NULL у гостя), display_name, added_by, joined_at.
- `entries`: id, game_id, player_id, kind (`buyin`/`rebuy`), created_by (кто нажал),
  created_at, cancelled_at (NULL — действует).
- `stacks`: game_id, player_id, chips, entered_by, entered_at.

Докупы — отдельные строки (`INSERT`), а не счётчик в одном документе: одновременные нажатия не
затирают друг друга. Повторное «Я в игре» того же пользователя — идемпотентно (уникальность
game_id + tg_user_id).

## Сценарий

### Старт
`/game <фишек за закуп> <цена закупа>`, например `/game 1000 50`. Цена допускает копейки
(`/game 1000 50.5`). Если в чате уже есть активная игра — бот отвечает ссылкой на неё.

Бот публикует игровое сообщение и дальше **редактирует его** при каждом изменении:

```
🃏 Игра · 1000 фишек = 50
Паша    2 закупа  · 100
Дима    1 закуп   ·  50
Вася 👤  1 закуп   ·  50
Банк: 4000 фишек · 200
[Я в игре] [+ Докуп]
[Добавить гостя] [Пригласить ↗]
[↩ Отменить] [Закончить]
[Отменить игру]
```

### Присоединение
- **«Я в игре»** — нажавший добавляется с одним закупом.
- **«Пригласить ↗»** — URL-кнопка `t.me/<bot>?start=join_<game_id>`. Её можно переслать кому
  угодно. Человек жмёт Start в личке бота → попадает в игру с одним закупом → бот присылает ему
  в личку его личное сообщение с кнопкой «+ Докуп» (для себя). URL-кнопка выбрана потому, что
  поведение callback-кнопок в пересланных сообщениях ненадёжно.
- **«Добавить гостя»** — бот просит ответить на его сообщение именем (ForceReply). Гость
  получает один закуп и пометку 👤.

### Докуп
- **«+ Докуп»** — если в игре нет гостей, докуп сразу записывается нажавшему. Если гости есть —
  бот показывает выбор «Себе / Вася 👤 / …»; докуп за другого Telegram-игрока нельзя.
- Нажавший не в игре → всплывающее уведомление «Сначала „Я в игре“».
- Каждая запись хранит, кто её создал; в игровом сообщении (или по отдельной кнопке истории —
  на усмотрение исполнителя) видно «Паша → докуп Васе».
- **«↩ Отменить»** — отменяет последнюю **свою** действующую запись нажавшего (свой докуп или
  докуп, который он поставил гостю). Начальный закуп отменяется так же — это выход из игры.

### Конец игры
**«Закончить»** (любой участник) переводит игру в `counting`. Бот присылает сообщение подсчёта:

```
Введите стеки — ответом на это сообщение числом.
За другого: «Вася 800».
Паша  1370 ✓
Дима  —
Вася 👤 —
[У меня 0] [Вернуться в игру]
```

- Ввод стека — **ответ (reply) на сообщение подсчёта** числом; бот в группе видит ответы на свои
  сообщения даже в privacy mode. Просто число — свой стек. «Имя число» — стек **любого**
  игрока (гостя или ушедшего Telegram-игрока); решение пользователя. Повторный ввод
  перезаписывает. Если стек ввёл не сам игрок, в сообщении подсчёта видно, кто: «Дима 500
  (ввёл Паша)». Имя сопоставляется с display_name без учёта регистра; при неоднозначности бот
  просит уточнить.
- Игрок из лички вводит стек в личке бота.
- **«Вернуться в игру»** — назад в `active`, введённые стеки сохраняются.

Когда введены стеки всех игроков — сверка.

### Сверка и расхождение
Банк в фишках = (число действующих записей) × chips_per_buyin. Сравнивается с суммой стеков.

```
⚠️ На столе 7000, в банке 6000 — расхождение +1000 (50,00)
[Дописать докуп] [Разделить на всех]
```

- **«Дописать докуп»** — возвращает в `counting` с той же клавиатурой докупа (выбор игрока),
  затем сверка заново.
- **«Разделить на всех»** — расхождение в деньгах делится **поровну между всеми игроками**
  (в обе стороны: и когда фишек больше, и когда меньше). Неделимые копейки — по одной первым
  игрокам в порядке входа.

### Расчёт
Результат игрока, коп = стек × price_kop / chips_per_buyin − вложено, коп.
Деление может давать доли копейки → округляем каждого до копейки, затем остаток распределяем
так, чтобы сумма по всем была ровно 0 (метод наибольших остатков).

Минимум переводов:
- Игроки с нулевым балансом не участвуют.
- Если ненулевых ≤ 15 — **точный минимум**: число переводов = n − (максимальное число
  непересекающихся подмножеств с нулевой суммой), DP по битовым маскам; внутри каждого
  подмножества — жадное сведение должников с кредиторами.
- Если больше 15 — жадный алгоритм (не больше n − 1 переводов).
- Ограничение 15 — из-за лимита CPU на бесплатном Cloudflare (10 мс на запрос); исполнитель
  проверяет замером и может сдвинуть.

Вывод (точный, до копейки):
```
✅ Итог
Дима → Паше 34,25
Вася → Паше 15,75
Вася → Саше 12,10
[Округлить]
```

**«Округлить»** — балансы округляются до целых, весь остаток округления отдаётся одному
игроку (самому большому выигравшему), затем переводы пересчитываются. Обе версии доступны
(кнопка переключает «Точно / Округлить»).

После расчёта игра `settled`; в чате можно начать новую `/game`.

### Правка цены и отмена игры
Решение пользователя: доступно **любому** участнику чата, бот пишет, кто это сделал.

- `/price <фишек за закуп> <цена закупа>` — меняет параметры активной (или в подсчёте) игры.
  Пересчитывается всё, игровое сообщение обновляется, в чат — «Паша изменил: 1000 = 50».
- **«Отменить игру»** (в игровом сообщении) → подтверждение «Точно отменить? [Да] [Нет]» →
  статус `cancelled`, сообщение помечается «❌ Игра отменена (Паша)». Чат свободен для новой
  `/game`. Записи в базе остаются.

## Тестирование

- `core/` покрыт `node --test`: сумма балансов = 0 всегда; число переводов на известных
  случаях равно минимуму; сверка точного DP с перебором на случайных малых наборах;
  копейки/округление; расхождение в обе стороны; деление неделимого.
- Обёртка — ручная проверка на тестовом боте в тестовой группе (`wrangler dev` + туннель или
  деплой в отдельный worker).

## Что оставлено исполнителю

- Точные тексты сообщений и эмодзи.
- Как показывать историю записей (в сообщении или по кнопке).
- Формат callback_data (≤ 64 байт).
- Вёрстка: что делать, если игровое сообщение не удалось отредактировать (например, удалено) —
  разумно прислать новое и обновить message_id.
- Настройка wrangler, миграций и деплоя; инициализация git.

## Решения, принятые мной (не пользователем)

- Докуп за другого Telegram-игрока запрещён; за гостя — можно любому.
- «↩ Отменить» отменяет только свою последнюю запись.
- Стеки вводятся ответом на сообщение подсчёта (за другого — «Имя число»).
- Отмена игры — с подтверждением; записи в базе не удаляются.
- Неделимые копейки при «Разделить на всех» — первым по порядку входа.
- Остаток при «Округлить» — самому большому выигравшему.
- Порог точного алгоритма — 15 ненулевых игроков.
- Одна активная игра на чат.
